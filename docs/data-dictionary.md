# Data Dictionary

This documents both the source of truth (`data/calendar.csv`) and the
generated runtime asset (`assets/bs_data.json`, schema 2).

## data/calendar.csv (source of truth)

One row per Bikram Sambat year. Plain CSV, UTF-8, no quoting needed for
current data.

| Column | Type | Meaning |
|--------|------|---------|
| `bs_year` | int | Bikram Sambat year (1975–2083). |
| `baisakh1_ad` | date (yyyy-MM-dd) | AD date (Nepal civil calendar, NPT = UTC+05:45) of Baisakh 1 for that year. Anchors the whole chain. |
| `m01` … `m12` | int | Days in each month: Baisakh, Jestha, Ashad, Shrawan, Bhadra, Ashwin, Kartik, Mangsir, Poush, Magh, Falgun, Chaitra. Each in 29–32. |
| `evidence` | enum | `verified` = official panchang (NPNS / Surya). `consensus` = multiple independent open datasets agree. `disputed` = competing community variants exist; the row ships as-is. `projection` = derived, not official (never shipped as fact). |
| `sources` | string | Provenance tag(s), space-separated (e.g. `npns-panchang-2083 open-datasets`). |
| `notes` | string | Free text (e.g. agreement counts, correction history). |

### Disputed years (kept `disputed`, never silently resolved)

1989, 1991, 1993, 2004, 2062 — two community variants exist for each;
the shipped variant matches the sambat reference and portal triangulation
for 2004/2062. Real resolution requires archival sources (Gorkhapatra
mastheads, NPNS volumes) — see Linear HYA-359/HYA-365.

## assets/bs_data.json (schema 2, generated)

Generated by `scripts/gen_bs_data.py`. **Never hand-edit** — regenerate:

```bash
python scripts/gen_bs_data.py
```

```jsonc
{
  "schema": 2,
  "source": "…provenance note…",
  "years": [
    {
      "bsYear": 2083,
      "baisakh1Ad": "2026-04-14",     // anchor of the year
      "monthLengths": [31, 31, 32, 31, 31, 31, 30, 29, 30, 29, 30, 30],
      "evidence": "verified",
      "sources": "npns-panchang-2083 open-datasets",
      "notes": "checked against the national panchang; 8/20 open datasets agree"
    }
    // … 109 rows, BS 1975–2083
  ]
}
```

The full month/day grid is expanded at runtime by `BsCalendarEngine`
(`lib/services/bs_calendar_engine.dart`): month AD spans, per-day AD dates,
and weekday names are all derived from the anchor + month lengths, so the
asset stays ~30 KB instead of ~8.6 MB.

Schema 1 (legacy, pre-expanded `months` list) is still accepted by
`BsDataService.load()` for backwards compatibility.

## Invariants (CI-enforced via tests and the codegen --check)

1. Years are contiguous: 1975 … 2083 (109 rows).
2. Every month length is 29–32 days; every year totals 364–367 days
   (the sidereal year is ~365.26 days).
3. Chain closure: Baisakh 1 of year N+1 = Baisakh 1 of year N plus the
   total days of year N. Every month starts the day after the previous
   month ends.
4. Evidence class is one of the four allowed values (never empty).
5. `assets/bs_data.json` is the parsed-equal output of the codegen script
   applied to `data/calendar.csv`.

Not yet machine-checked (tracked in Linear): the era-aware sankranti-window
invariant (HYA-358) — month starts must fall within [sidereal ingress NPT
date, +1 day] from BS 2036 on — which needs the Commons Layer 1 sankranti
moments CSV.
